## What this project is

A Next.js 14 + TypeScript web app that turns a brief into a finished, on-brand, ready-to-publish social media post (Instagram + LinkedIn). Two generation paths:

- **Path A** — HTML/CSS brand template (stored in DB), Claude agent fills it → Puppeteer renders PNG
- **Path B** — Claude agent generates freeform HTML/CSS design → Puppeteer renders PNG

Stack: Next.js 14, TypeScript, Prisma, PostgreSQL, MinIO, better-auth (self-hosted), Docker Compose. Puppeteer (headless Chromium) for HTML→PNG rendering. Claude agent harness (Anthropic SDK tool-use loop) drives design generation.

## Architecture decisions to remember

- All AI calls are **server-side only** — the browser never calls an AI API or Puppeteer directly
- **Roles are hierarchical:** `SUPER_ADMIN > ADMIN > EDITOR`; every check goes through `hasRole()` (`src/lib/roles.ts`) — never compare role strings directly. Super-admins pass every admin gate. User management (`/admin/users`) is super-admin-only; "delete" = deactivate (`User.disabled`, sessions revoked, sign-in blocked).
- **Sign-in is by username** (better-auth `username()` plugin); email exists internally only (`<username>@users.bistec.internal` synthesized for admin-created accounts). Seeded dev admin: `adminBTG`.
- **Brand kit precedence:** Explicit brief kit (`Brief.brandKitId`) → Campaign kit → Project default → system default (`BrandKit.isDefault = true`)
- **Post size:** chosen per brief (`Brief.aspectRatio`: `SQUARE`=1080×1080, `PORTRAIT`=1080×1350); a brand template declares the size it was designed for (`BrandKitTemplate.aspectRatio`). Dimensions resolve through `src/lib/aspectRatio.ts` — the only place pixel sizes are defined.
- **AI provider resolution order:** Brief's chosen key → `AvailableProvider.isDefault` → env var fallback
- **Claude model resolution (008):** one catalogue, `src/lib/models/catalogue.ts`, is the only place a model ID or alias may appear in `src/` (a guard test enforces it). Every call names a surface and resolves through `resolveModel`: explicit pick (or the brief's stored initial request) → the draft's stamp (regenerate only) → the team default (`/team` → Models) → the system default (`CLAUDE_CLI_MODEL` in CLI mode, then the table) → fallback. The team allow-list is checked at every tier at call time; only an explicit pick returns 400, and a stored value that is no longer allowed is substituted and recorded. Choices are stored as keys (`HAIKU`/`SONNET`/`OPUS`); stamps record the full ID that ran.
- **Fonts (031):** the Google Fonts catalogue is a snapshot, `src/lib/fonts/catalogue.json` (dated 2026-10-26; 1950 families; never fetched at runtime). `src/lib/fonts/catalogue.ts` holds the lookup `findFamily`, `url.ts` builds the request with `googleFontsUrl`, and save validation runs in `validateKitFonts` and `validateScriptFonts`. A kit's `BrandKit.scriptFonts` (Sinhala only, empty by default) feeds the font stacks through `scriptFonts`. At the three design writers (Path A, Path B and refine) `applyPostFonts` (`src/lib/fonts/inject.ts`, pure) adds the marked font request and the stack entries; a guard test covers the call sites. A family that does not render is recorded in `renderNotes.fontsMissing` on the stamp and shown as a notice. `/api/fonts` serves the picker. Refresh the snapshot with `node scripts/refresh-google-fonts.mjs`, an operator step (see `docs/cold-start.md`); it never runs in CI and never removes a family (it marks a missing one `delisted`).
- **Image generation key (031):** a user can connect a personal OpenAI or Gemini key at `/settings`, stored in `UserOpenAiKey` with a new `provider` column (additive; `openai` for old rows). `detectKeyProvider` (`src/providers/keyPrefix.ts`, pure, shared by the server, `/team` and the card) decides the provider from the prefix; an unknown prefix is refused with 400 and nothing is stored. The resolver (`resolveImageProviderWithSource`) tries the personal key first, falls back once to the team provider with a notice, and stamps `Draft.imageSource` with the tier that served the image. The live Gemini call is not verified (mock only, L1).
- **Apply to image (031):** `src/lib/applyText/` (candidates, the splice, the append-only failure list `APPLY_FAILURES`) and the route `POST /api/drafts/[id]/apply-text`. It runs only on a `stale` headline (422 `not-stale` otherwise), claims the draft under the `APPLY_TEXT` action, splices the new headline into the HTML with `parse5` and renders it through `commitDraftRevision` with `acceptRender`. The in-render check (`src/lib/renderedText/`, T14) is fail-closed: a render where the new headline is not painted, or the old one still is, writes nothing and names the reason. The event is `draft.text_applied` (no text in the payload). `APPLY_TEXT_BETA` is `false`: the re-measure on `bistec_studio_op1` passed 35 of 36 (97.2%, a non-representative sample), so there is no Beta chip. Undo restores the previous revision.
- **Wording guard (031):** the glossary is `docs/ui-reference/DESIGN_SYSTEM.md` §12 "Words" ("post", not "brief"; Template and Freeform; Brand kit; Team settings; sentence case; US spelling). `tests/unit/uiWordingGuard.test.ts` scans string literals and JSX text in `src/app/(app)/**` and `src/components/**` against `WORDING_PATTERNS`, and fails on a deny-listed phrase. A line opts out only with `// wording-exception: <reason>`. Messages in `src/lib` are fixed by hand, not by the guard. Routes, API fields and DB names do not change.
- **Hero imagery (009):** a Path B brief carries an optional `Brief.imageStyle` (`classic` default, `product-showcase`, `editorial-split`, `full-bleed-scene`, `spotlight`). Since 028 every current look supports SQUARE, PORTRAIT and STORY, so 9:16 is no longer excluded for interactive Path B briefs; scheduled, MCP and ACP briefs are always classic. `src/lib/designData/` is the single source of the layout regions (007 extends it). Every draft and revision carries a `composition` stamp (null means "before 009"). A hero image that fails the real-pixel check fails closed: it is reused under the classic prompt, with no second image call.
- **Scheduler health (023):** each worker loop writes a `WorkerHeartbeat` row through `runTick`; `GET /api/scheduler/status` reports it via the pure `loopHealth` rule, and the campaign queue panel shows a "Scheduler offline" banner.
- **Caption registry (026):** `CAPTION_CHANNELS` in `src/lib/channels.ts` holds Instagram and LinkedIn only (a draft has two captions; WhatsApp was removed on 2026-10-23, and 010 is dropped). Legacy WhatsApp `DraftCaption` rows are hidden by registry ordering and never deleted. Any new reader of caption rows must go through `loadDraftCaptions`, and any bulk caption write must be scoped to registry channels (`channel: { in: CAPTION_CHANNELS.map(s => s.channel) }`). `CHANNEL_LABELS` keeps `WHATSAPP` for old `Post` rows. On the draft page the Refine Design card sits under the Preview card in the left column, and Captions is the right column.
- **Caption route (024):** a team's caption credential is a stored setting, `Team.captionRoute` (`CLI` or `API_KEY`; null means never chosen, which keeps the old rule: the brief's key, then the default COPY row, then the CLI). One pure selector, `selectRoute('CAPTION', input)` in `src/lib/models/route.ts`, decides the route and the row; `loadCaptionRoute` feeds it, `resolveCopyProvider` and `copyProviderIsClaude` call it, and `GET /api/team/caption-route` shows the same answer to `/team`. A chosen route with no usable credential **fails closed** with a route-named error and never falls to the other route or the server key. The route that ran is stamped on each caption row and the headline (`DraftCaption.route`, `Draft.headlineRoute`: `CLI`, `API_KEY`, `SERVER_KEY` or `OTHER`; null means before 024), and the `MOCK_AI` model-calls record carries it as `route`. An `API_KEY` run counts as the team credential tier for the Opus gate (`captionCredential` on `GET /api/models`). Under a chosen route a brief's stored `copyProviderKey` is `'cli'` and is ignored. `modelArgParity.test.ts` pins `apiId === cliArg` for every catalogue entry.
- **Analytics (006):** the app keeps an append-only event store in its own Postgres (`AnalyticsEvent`, plus `AnalyticsDrop` counters), written only through `track(name, fields)` in `src/lib/analytics/track.ts`. **One emitter per event name:** each event has exactly one place that writes it, and a shared function that serves several surfaces takes an explicit `source` (`web`, `scheduler`, `mcp`). `track` never throws in production and is bounded at 2 s; a dropped or rejected event is counted in `AnalyticsDrop` and shown on the page. Under `MOCK_AI` or `NODE_ENV=test` an invalid payload throws. The catalogue (`src/lib/analytics/catalogue.ts`) holds each name's zod schema and `schemaVersion`; vocabularies (Prisma enums, model catalogue keys, 009 archetype keys) are **imported, not copied**, and `analyticsCoverage.test.ts` fails if a `DraftAction`, `Channel` or `source` value has no event that can carry it. A change that adds an action, a channel, a generation path or a publish path owns its events. Events hold ids, enums, counts, durations, redacted failure reasons and the capped refine instruction, never prompt text, model output, captions or headlines. `POST /api/events` takes only the client event `wizard.step` and sets team, user and source from the session. The read seam for tests is `/api/test/analytics-events` (404 in prod and without `MOCK_AI`, admin only). Reads go only through `src/lib/analytics/queries.ts`; the page is `/admin/insights`, super admin only. Retention is 180 days, swept by a third worker loop (`retention`, 5 000 rows per tick, not in the scheduler banner). `scripts/purge-analytics.mjs` refuses to run without an explicit `DATABASE_URL`. New migration `20261024120000_analytics_events` (manual down script `prisma/rollback/006-product-observability.down.sql`); no env var.
- **Post styles (027):** a post style is code-owned data in `src/lib/postStyles/` (a sibling of `designData/`, which never imports it): eight styles (`general`, `launch`, `promotion`, `event`, `hiring`, `announcement`, `tip`, `milestone`), each with a goal, a default tone, a default image style and a checklist of measurable rules marked `caption` or `image`. **The key rule:** a key is never reused for a different meaning and never renamed; a retired style stays resolvable and is hidden from pickers; a future team-owned style gets its own id column. **The version rule:** a released version is never edited; add `versions[n+1]`. **One resolver:** `resolvePostStyle` (`resolve.ts`, pure) is the only place a style maps to a goal, tone, image style and checklist, and every surface calls it (wizard, `POST /api/briefs`, queue and runner, MCP, ACP, regenerate); `postStylesBoundary.test.ts` fails on any other mapping. Precedence is explicit style, campaign default, `general`. An unknown key is a 400 at write and a named failure at run, never "no style". **`goal` is a snapshot** written only by the server from the style; a legacy `goal` with no `postStyle` picks `hiring`, `announcement` or `general`. **Stamps and versions:** `Draft.postStyle` and `DraftRevision.postStyle` hold `{ key, version, revision }`; `PROMPT_VERSION` and `CAPTION_PROMPT_VERSION` end in `+ps<POST_STYLES_REVISION>`, derived from the dataset; refine uses the stamped version. **The facts check** (`src/lib/factsCheck/`, pure, no model call, never throws) compares numbers, dates, times, currency, percentages and phone numbers in the headline and the Instagram and LinkedIn captions with the brief, the campaign briefing, the kit voice text and the campaign documents, and stores `Draft.factsCheck` (`clear`, `flagged` or `error`; matched values and where, never text). It runs on every generation and recomputes on regenerate copy and on a caption or headline edit. **The HOLD rule:** a `SCHEDULE_PUBLISH` or `PUBLISH_NOW` entry whose check is `flagged` or `error` creates no `Post`; it settles `COMPLETED` with its draft and a `heldReason`, and a re-run clears it. MCP and ACP `generate_post` never publish and are not blocked. Known limits L1 to L7 are in the handoff 027 section; the check does not read the HTML. The "Post styles" section of `/admin/insights` shows chosen, generated, flagged and held per style. The ACP manifest is `1.2.0`. New migration `20261025120000_post_styles` (manual down script `prisma/rollback/027-post-styles.down.sql`); no env var.
- **Image looks (028):** a look is one key in `src/lib/designData/composition.ts`, with versions of contracts per size. Four looks are current: `product-showcase` (v2; SQUARE, PORTRAIT and STORY), `editorial-split` (v2; the same three sizes), `full-bleed-scene` (v1; a calm text band along the bottom) and `spotlight` (v2, current since 031 T18; a headline band at the top, a call-to-action band at the bottom, the subject centred; v1 stays resolvable for stamps and is kept as `SUPERSEDED_FIXTURES` in the render suite).
