## Findings

### [WARN] src/lib/drafts/download.ts:45,77 - AC-07 "second call does not render" fails when the revision's exportUrl is set but differs

`const current = draft.exportUrl != null && (!revision || revision.exportUrl === draft.exportUrl)` and `if (revision && revision.exportUrl === null)`. When draft.exportUrl differs from a non-null revision.exportUrl, the CAS rewrites only the draft key and leaves the revision's alone, so the next call mismatches again and re-renders and re-uploads on every download (the unit test "leaves a set revision key alone" never makes the second call). Fix: in that case also set the revision's exportUrl to the new key (or compare against the revision only when it is null-filled) and add a second-call assertion to that test.

### [NOTE] src/app/api/drafts/[id]/download/route.ts:62 - storage read failure emits no event

`getObjectBytes` throwing after a successful ensure gives an unhandled 500 with no `draft.downloaded`. Fix: wrap in try/catch and track `outcome: 'failed'` (would need a failure code in DOWNLOAD_FAILURES), or accept.

### [NOTE] tests/e2e/download.test.ts - AC-08/404 parity and filename safety not covered end to end

TC-DL-03 checks only an unknown id; no cross-team/invisible case compares body parity. Code is correct (both paths return `{ error: 'Draft not found' }`, 404), so only coverage is thin.

### [NOTE] src/app/(app)/drafts/[id]/page.tsx - filename regex

`/filename="([^"]+)"/` is fine because the server slug is `[a-z0-9-]` only; no change needed.
