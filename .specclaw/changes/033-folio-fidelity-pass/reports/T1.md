## Permit-citation rule chosen

`parsePermits` returns `permits` (each with `rowId`, `sign`, `file`, `key`, `status`), `rows` (Map ID to Status), `duplicates` and `files`. `judge(diff, permits, rows, duplicates)` fails a permit whose `rowId` is not `A-NNN` or not in `rows`, fails a permit on a row whose Status is not `approved` / `closed ...` (and such a permit consumes nothing, so the diff fails too), and fails on a duplicated row ID. Unused permits are warnings. I added `duplicates` as an optional fourth argument to `judge` because a Map cannot hold duplicates. Documented in the module header.

## Review fixes

1. Permits cell: each token is now one markdown code span; a value with a backtick uses a double-backtick span with one space of padding. Documented in the module header and the audit.md legend. A non-dash cell with no code span is malformed and fails.
2. `\|` is supported in every cell (split on unescaped pipes, then unescape). Permit values are written without the JSX braces, as the key is (`href=a \|\| b`).
3. A permit consumes a removal or addition only when its file is among the key's files; a wrong-file permit leaves the diff failing and warns as unused.
4. Status check is `approved` exactly or `closed <sha>` (`approvedX` is rejected).
5. New cases (26 total): template-literal permit, escaped-pipe permit, wrong-file permit, `+` permit on a removal, added duplicate (1 to 2), permits on `cut`, `behaviour`, `approvedX` and `proposed` rows, malformed (unwrapped) cell. Existing permit fixtures were converted to code spans.
