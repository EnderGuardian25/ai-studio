## How to classify (the edge rule)

- **look** — returns to Folio: section structure, rules, numbering, labels, type, spacing, cards, pills, tinted badges, rounded boxes, icon-only buttons where Folio shows a word, copy that differs from Folio's text under §12. The Fix says concretely what changes, citing `9f829456:<file>:<line>` or `DS §x.y`.
- **behaviour** — stays: a feature, flow, condition, data, or an arrangement that a 018–031 change's `proposal.md` or `spec.md` **names** (e.g. 026's Refine design under the Preview; 020's floating Create post button). The Reference cites the change and the file:line of that sentence. No citation → not behaviour.
  - **021 (`021-graphite-retheme`) is the Graphite retheme that 032 reverted.** A 021 citation for a styling or structure choice does not make it behaviour; such a difference is `look`. If 021 names a structural arrangement that also carries a feature, mark it `ambiguous` and ask.
- **ambiguous** — unclear after checking; the Fix column holds the question for the user, phrased so it can be answered with a choice.
- **none** — a file whose diff has no look difference (e.g. only behaviour-level code, imports, handlers); one `none` row with Fix `—`.
- New features inside an audited file (e.g. a 018–031 notice rendered on the draft page) are behaviour by default _for their presence and placement only if named_; their styling is still look.

## Row granularity and content

- One row per distinct difference (an element or a contiguous line range at `c45ed3dc`), not per class token. Group trivially repeated differences in one file into one row when the same fix applies.
- **Element** names the JSX element and its line range at HEAD (HEAD == `c45ed3dc` for src except T3's four files).
- **Permits**: needed only when a Fix would add/remove/change a guarded attribute (`aria-*`, `data-testid`, `role`, `id`, `htmlFor`, `type`, `name`, `href`, `on*`, spreads). One token per count, in the legend's code-span format. Prefer fixes that need no permit; a fix that would change a `data-testid` or handler is probably behaviour.
- **Primitives** (`ui/{PageHead,FieldLabel,Notice,StatusChip}.tsx`, and anything a row says belongs in `atoms.ts`): rows sit in the family design §2.1 names; say in the Fix that the change lands in T6. Never propose a change to the 17 pinned files (design §2.3) or to `Panel`/`SectionHead`; if one seems needed, make it `ambiguous`.
- Rows never touch the NFR-01 paths (`src/lib`, `src/app/api`, `src/providers`, `src/scheduler`, `src/mcp`, `src/scripts`, `prisma`).
- `brief/constants.ts` and `brief/useBriefWizard.ts` are audit-set `.ts` files: audit their class/copy data; if nothing is look, a `none` row.
