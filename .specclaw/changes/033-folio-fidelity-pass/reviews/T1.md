## Findings

### [WARN] scripts/lib/uiInvariants.mjs:102,116,125 — permit cell loses a trailing backtick

`const unwrap = (c) => c.replace(/^`+|`+$/g, '')` is applied to the whole Permits cell. A permit for a template-literal value, e.g. `-f.tsx:id=\`x-${i}\``, parses to key `id=\`x-${i}`(verified by running it). collectAttrs emits`id=\`x-${i}\``, so the permit never matches: the diff fails and the permit is only an "unused" warning. Fails safe, but a legitimate permit cannot be written. Fix: strip backticks only when the cell both starts and ends with one (`/^`(.*)`$/s`), or have T4 use a doubled-backtick code span.

### [WARN] scripts/lib/uiInvariants.mjs:101 — `|` in a value breaks the table parse

`cells()` splits on `|`. For `href={a || b}` the permit is `href=a` and the Status column becomes the wrong cell (verified: status `''`), so the permit is rejected. No `\|` escape handling. Fails safe, but an expression with `||` cannot be permitted. Fix: split on unescaped `|` and unescape `\|` in the key (document it in audit.md's legend).

### [NOTE] scripts/lib/uiInvariants.mjs:147 — permit file is never checked

Matching is by key only; `p.file` is used only in the message. `-wrong.tsx:data-testid=save` satisfies a removal made in another file. Consistent with whole-scope keying, but a permit's file could be checked against the diff entry's `files` and against the row's File column.

### [NOTE] scripts/lib/uiInvariants.mjs:146 — status regex is loose

`/^(approved|closed\b)/` accepts `approvedX`; `approved` lacks `\b`. Use `/^(approved|closed\b)\b/` or compare exactly.

### [NOTE] scripts/check-ui-invariants.mjs:38 — no zero-file guard

git errors do throw (execFileSync), so they are not swallowed, but if both lists were empty the script would print "ok". Add `if (!baseFiles.length || !headFiles.length) process.exit(2)`. A file that fails to parse yields partial attributes without error (TS is error-tolerant); consider failing on `sf.parseDiagnostics.length`.

### [NOTE] tests/unit/uiInvariants.test.ts — untested branches

No test for a wrong-direction permit (a `+` permit on a removal; logic is correct, it warns and the removal fails), an added duplicate (count 1 to 2), or a permit on a `cut`/`behaviour` row (only `proposed` is tested; the regex covers it). Cheap to add.
