`findOrCreateDraft` returns `library.drafts[0]` (newest). It now runs once, before the notice drafts are created, but on every rerun against the same DB the newest draft is a notice draft (headline-unconfirmed, created last), so the pre-existing `draft` screen changes from run to run. ref-shots.mjs also takes the newest EXPORTED draft (`/api/library?pageSize=1`). In gate.sh it runs before capture-ui on a freshly reset DB, so the gate is safe, but any manual capture-ui run on the stack before a manual ref-shots run (e.g. T11 recapture without a reset) would put a notice banner into docs/ui-reference/screen-*.png. Fix: make the sample draft deterministic, e.g. look it up by topic 'UI capture sample post' (search param, as the notice drafts do) and only fall back to the newest; or note in T11 that ref-shots must run first / after a reset.
