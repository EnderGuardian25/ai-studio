### [WARN] src/components/brief/SelectedTemplatePreview.tsx:34 - A11y / Design adherence

`<FieldLabel className="mb-2">Preview</FieldLabel>` defaults to `as="label"` with no `htmlFor`: an orphan `<label>` that labels nothing. FieldLabel's own comment says `as="span"` is for captions of a group. Likely trips an a11y rule (AC on a11y.test.ts) and is semantically wrong.

### [WARN] src/components/brief/SizeDesignStep.tsx:343-349 and :383-389 - Correctness (stale selection)

`{templateId && <SelectedTemplatePreview id={templateId} ... />}` gates on the raw id, not on `visibleTemplates`. The hook clears stale ids only in a `useEffect` (useBriefWizard.ts:555-556), so after a kit or size change there is one render where the old id is still set: the preview mounts and `useQuery` fires a fetch for a template no longer offered (the `?? 'template'` name fallback hides this). After the effect the id is '' and it unmounts, so no lasting stale preview, but it costs a wasted request and a flash. Preview showing for a non-visible template is possible for that one pass.
Fix: compute `const selected = visibleTemplates.find(t => t.id === templateId)` and render `{selected && <SelectedTemplatePreview id={selected.id} name={selected.name} .../>}` (same for reference). That also removes the `?? 'template'`/`'reference'` fallbacks.

### [NOTE] src/components/brief/SelectedTemplatePreview.tsx:30 - Complexity

`if (!id) return null` after the hook is dead given both call sites already gate on a truthy id; `enabled: !!id` likewise. Harmless defensive code; drop one layer if the gate above is tightened.

### [NOTE] src/components/brief/SelectedTemplatePreview.tsx:36 - A11y

`role="status"` on a `<p>` that mounts already containing text is often not announced (live regions must exist before content changes). Acceptable for a non-blocking hint; optional to leave.
